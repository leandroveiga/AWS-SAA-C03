# Amazon S3 (Simple Storage Service)

O **Amazon S3** é um serviço de armazenamento de **objetos** que oferece escalabilidade, disponibilidade de dados, segurança e performance líderes do setor. É um dos serviços mais antigos e fundamentais da AWS.

-   **Armazenamento de Objetos:** Diferente de um sistema de arquivos tradicional (que usa uma hierarquia de pastas), o S3 armazena dados como "objetos" dentro de "buckets". Cada objeto consiste em dados, uma chave (o nome do objeto) e metadados.
-   **Escala Ilimitada:** Você pode armazenar uma quantidade ilimitada de dados.
-   **Durabilidade de 11 noves (99.999999999%):** O S3 é projetado para nunca perder seus dados, replicando-os automaticamente em múltiplas Zonas de Disponibilidade.

---

## Classes de Armazenamento (Storage Tiers)

Escolher a classe de armazenamento correta é crucial para otimizar custos.

| Classe de Armazenamento | Caso de Uso Principal | Durabilidade | Disponibilidade |
| :--- | :--- | :--- | :--- |
| **S3 Standard** | Dados acessados com frequência (sites, distribuição de conteúdo) | 11 noves | 99.99% |
| **S3 Intelligent-Tiering** | Dados com padrões de acesso desconhecidos ou variáveis | 11 noves | 99.9% |
| **S3 Standard-IA** | Dados acessados com pouca frequência, mas que precisam de acesso rápido | 11 noves | 99.9% |
| **S3 One Zone-IA** | Dados secundários ou facilmente recriáveis, acessados com pouca frequência | 11 noves | 99.5% |
| **S3 Glacier Instant Retrieval** | Arquivo de longo prazo que precisa de recuperação em milissegundos | 11 noves | 99.9% |
| **S3 Glacier Flexible Retrieval** | Arquivo de longo prazo com recuperação flexível (minutos a horas) | 11 noves | Offline |
| **S3 Glacier Deep Archive** | Arquivo de longo prazo mais barato, com recuperação em horas | 11 noves | Offline |

-   **S3 Intelligent-Tiering:** Move automaticamente seus dados para a camada de armazenamento mais econômica com base na frequência de acesso, sem impacto no desempenho ou sobrecarga operacional. É uma ótima opção "configure e esqueça".
-   **One Zone-IA:** Armazena dados em uma única AZ. É mais barato, mas **os dados serão perdidos** se essa AZ falhar. Use apenas para dados não críticos.

## Segurança no S3

A segurança no S3 é multifacetada e um tópico muito importante.

### 1. Controle de Acesso

-   **IAM Policies:** Políticas baseadas em identidade, anexadas a usuários, grupos ou roles, definindo quais chamadas de API do S3 eles podem fazer.
-   **Bucket Policies:** Políticas baseadas em recurso, anexadas diretamente a um bucket S3. Permitem conceder acesso cross-account (para outras contas AWS) ou acesso anônimo.
-   **Access Control Lists (ACLs):** Um mecanismo legado para conceder permissões básicas de leitura/escrita a outras contas AWS. **Boa prática:** Use políticas de bucket e IAM em vez de ACLs.
-   **S3 Block Public Access:** Uma configuração no nível da conta ou do bucket que fornece um controle centralizado para impedir o acesso público aos seus buckets e objetos. **Está habilitado por padrão para novos buckets.**

### 2. Criptografia

-   **Criptografia em Trânsito (In-Transit):** Protegida usando HTTPS (TLS/SSL) ao fazer upload/download de objetos.
-   **Criptografia em Repouso (At-Rest):**
    -   **SSE-S3 (Server-Side Encryption with S3-Managed Keys):** O S3 gerencia as chaves de criptografia. É a opção mais simples.
    -   **SSE-KMS (Server-Side Encryption with KMS-Managed Keys):** O S3 usa o AWS Key Management Service (KMS) para gerenciar as chaves. Oferece mais controle, permissões centralizadas e trilha de auditoria sobre quem usou a chave.
    -   **SSE-C (Server-Side Encryption with Customer-Provided Keys):** Você fornece e gerencia suas próprias chaves de criptografia. O S3 as usa para criptografar/descriptografar e depois as descarta.
    -   **Criptografia do Lado do Cliente (Client-Side Encryption):** Você criptografa os objetos *antes* de enviá-los para o S3.

## Gerenciamento de Dados e Ciclo de Vida

-   **Versionamento (Versioning):** Mantém um histórico completo de todas as versões de um objeto. Protege contra exclusões acidentais ou sobregravações. Uma vez habilitado em um bucket, não pode ser desabilitado, apenas suspenso.
-   **Políticas de Ciclo de Vida (Lifecycle Policies):** Automatizam a movimentação (transição) de objetos entre diferentes classes de armazenamento ou a expiração (exclusão) de objetos após um certo período.
    -   **Exemplo:** Mover objetos do S3 Standard para o S3-IA após 30 dias, depois para o Glacier Deep Archive após 90 dias e, finalmente, excluí-los após 7 anos.
-   **Replicação (Replication):** Copia objetos automaticamente para um bucket de destino.
    -   **CRR (Cross-Region Replication):** Replica para um bucket em uma Região da AWS diferente. Usado para recuperação de desastres e para reduzir a latência de acesso para usuários em diferentes localizações geográficas.
    -   **SRR (Same-Region Replication):** Replica para um bucket na mesma Região. Usado para agregar logs ou para manter cópias dos dados sob diferentes propriedades de conta.

## Outros Recursos Importantes

-   **Hospedagem de Site Estático:** Configure um bucket S3 para servir o conteúdo de um site estático (HTML, CSS, JS, imagens).
-   **S3 Object Lock:** Impede que um objeto seja excluído ou modificado por um período fixo ou indefinidamente (modelo WORM - Write-Once-Read-Many). Usado para atender a requisitos de conformidade regulatória.
-   **S3 Storage Lens:** Fornece visibilidade em toda a organização sobre o uso e a atividade do armazenamento de objetos, com recomendações para otimizar custos e aplicar as melhores práticas de proteção de dados.
-   **Server Access Logging:** Fornece registros detalhados das solicitações feitas a um bucket. Útil para auditoria de segurança.
-   **Event Notifications:** Dispara notificações (para SNS, SQS ou Lambda) em resposta a eventos do S3, como a criação ou exclusão de um objeto.
