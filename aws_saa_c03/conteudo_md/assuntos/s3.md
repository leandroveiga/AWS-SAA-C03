## Amazon S3 (Atualizado – Escopo SAA-C03 2025)

O Amazon S3 é um armazenamento de objetos com 11 9's de durabilidade, escalável, seguro e integrado ao ecossistema AWS. Serve para dados de qualquer formato/tamanho (até 5 TB por objeto) acessados via API/SDK/CLI/console ou integrações (CloudFront, Athena, Glue, Lake Formation etc.).

### Casos comuns
- Sites estáticos (com CloudFront + OAC)
- Data Lake (Athena/Glue/Lake Formation)
- Logs (ALB/NLB/CloudFront/ELB, CloudTrail, VPC Flow Logs)
- Backups/arquivamento e restauração
- Conteúdo distribuído globalmente

## Classes de Armazenamento (2025)

| Classe | Uso Principal | AZs | Latência de Acesso | Observações |
|--------|---------------|-----|--------------------|-------------|
| S3 Standard | Acesso frequente, general purpose | >=3 | Milissegundos | Alta disponibilidade (99.99%) |
| S3 Intelligent-Tiering | Padrão imprevisível | >=3 | Milissegundos | Move automaticamente entre subníveis |
| S3 Standard-IA | Acesso infrequente crítico | >=3 | Milissegundos | Min 30 dias, fee por recuperação |
| S3 One Zone-IA | Acesso infrequente não crítico | 1 | Milissegundos | Menor custo, sem AZ redundancy |
| S3 Glacier Instant Retrieval | Arquivo com acesso raríssimo mas precisa ms | >=3 | Milissegundos | Substitui parte de casos IA antigos |
| S3 Glacier Flexible Retrieval | Arquivo (minutos / horas) | >=3 | Minutos (Expedited / Standard / Bulk) | Antigo "Glacier" |
| S3 Glacier Deep Archive | Arquivo de longo prazo | >=3 | Horas (Standard/Bulk) | Menor custo total |
| S3 Express One Zone | Latência ultra-baixa (single digit ms), workloads transientes | 1 | Sub-ms a ms | Billing por carregamento; ideal para analytics intermediário |

#### Intelligent-Tiering Sub-Tiers
- Frequent, Infrequent, Archive Instant, Archive Access (~hrs), Deep Archive Access (~dias). Movimento automático exceto transição para Archive *Access* / *Deep* (requer opt-in).

## Recursos-Chave e Conceitos

### Durabilidade vs Disponibilidade
- Durabilidade 99.999999999% (11 9's) – resultado de replicação entre múltiplos dispositivos/AZs.
- Disponibilidade varia por classe (ex.: Standard 99.99%, One Zone IA menor). Planeje RPO/RTO.

### Performance
- Throughput aumenta paralelizando uploads (Multipart Upload recomendado >100 MB; obrigatório >5 GB).
- Não é mais necessário prefix random (hash) para distribuição de carga – partição adaptativa.

### Criptografia
- Em repouso: SSE-S3, SSE-KMS, SSE-C, ou client-side encryption.
- Em trânsito: HTTPS obrigatório; usar TLS >=1.2.
- AWS KMS + S3: considerar quotas de requests KMS (usar bucket-level encryption ou reenvelopamento quando alto volume).

### Segurança de Acesso
Ordem de avaliação de bloqueios/permissões:
1. Bloqueios de Public Access (S3 Block Public Access) – nível conta/bucket.
2. Bucket Policy (resource-based) / Access Points Policies.
3. IAM Identity Policies / Permission Boundaries.
4. ACLs (legacy; usar só quando realmente necessário, ex. acesso entre contas em cenário específico ou Object Ownership).

Recomendações:
- Habilitar S3 Block Public Access por padrão.
- Usar S3 Object Ownership (Bucket owner enforced) para eliminar ACLs.
- Para acesso cross-account granular: Access Point + ARN específico ou IAM with conditions.

### S3 Access Points e Multi-Region Access Points
- Simplificam acesso a buckets compartilhados para múltiplos aplicativos/contas.
- Multi-Region Access Point fornece *global endpoint* com failover e otimização de roteamento.

### S3 Object Lambda
Permite modificar/transmutar objetos sob demanda (ex.: mascarar PII, transformar CSV→JSON) antes de devolver ao cliente.

### Replicação
- SRR (Same-Region Replication) e CRR (Cross-Region Replication).
- Suporta replica de: nova versão de objeto, tags, ACLs, enc batch replicas retroativas com *Batch Operations*.
- Requer versionamento habilitado.
- Replication Time Control (RTC) para SLA (<15 min) em cargas críticas.

### Lifecycle & Expiration
- Regras para transicionar classes e expirar versões antigas / marcadas como delete markers.
- Complementar a Object Lock (governance/compliance mode) para WORM e retenção legal.

### Logs e Observabilidade
- Server Access Logging (ou preferir CloudTrail Data Events para auditoria por objeto crítico – tem custo maior).
- S3 Storage Lens: métricas e recomendações de otimização de storage.
- Inventory: gera listagem diária/semanal – útil para auditoria de criptografia/replicação.

### Eventos
- Notificações (EventBridge, SQS, SNS, Lambda). Preferir EventBridge para filtros avançados multi-fonte.

### Custos – Otimização
- Evitar pequenos PUTs (consolidar buffers).
- Usar Compression + TTL (lifecycle) em logs.
- Avaliar Glacier classes para dados frios >90/180 dias.

## Hospedagem de Site Estático
- Definir website hosting (caso necessário redirecionamentos). Para produção: usar CloudFront + Origin Access Control (OAC) bloqueando acesso público direto ao bucket.
- Bloquear *public ACLs* e negar na bucket policy qualquer acesso que não venha de CloudFront origin access principal.

---
## Versionamento
- Protege contra deleção/overwrite acidental.
- Integra com MFA Delete (somente via CLI e conta root) – raramente usado por fricção operacional.

---
## Checklist de Arquitetura Rápida (Exame)
- Escolha de classe correta (custo x latência x redundância)
- Bloqueio de acesso público + IAM least privilege
- Uso de KMS quando requisitos de compliance / logs de acesso à chave
- Replicação para DR multi-região (RTC se SLA crítico)
- Lifecycle para redução de custo
- Integração com Athena / Glue para analytics
- CloudFront + OAC para distribuição global

---
## Exemplos de Pergunta (Raciocínio)
1. Necessário transformar dinamicamente objeto antes de servir → S3 Object Lambda.
2. Endpoint único resiliente multi-região para leitura global de dados replicados → Multi-Region Access Point.
3. Dados arquivados por 7 anos, recuperação raríssima → Glacier Deep Archive.
4. Workload analítica precisa ingest-latency muito baixa em lote temporário → S3 Express One Zone.
5. Auditor exige evitar qualquer exposição pública acidental → Ativar Block Public Access (todas as flags) + Object Ownership.

---
## Referências Rápidas
- Limite tamanho objeto PUT único: 5 GB (acima usar multipart).
- Máx. tamanho objeto: 5 TB.
- Número ilimitado de objetos por bucket (limitar por práticas de gestão e custo).
- Encryption default (2023+) SSE-S3 automática se nenhuma outra definida.

---
## Mini Glossário
- **OAC**: Origin Access Control (substitui OAI) para CloudFront→S3.
- **RTC**: Replication Time Control.
- **Inventory**: Relatório CSV/ORC/Parquet listando objetos.
- **Object Lock**: Imutabilidade (governance / compliance mode + legal hold).
- **Access Point**: Abstração com policy isolada para acesso segmentado.
